🎯 Apps & Monitoring

GET /api/apps

List all apps that have an API URL configured. Used by the terminal console list command.

Response
[ { "id": 1, "title": "Portainer", "api_url": "http://portainer:9000/api/status" } ]
GET /api/app/{app_id}/stats

Fetch live stats for a single app by calling its configured API URL. Returns a formatted display value based on the app's value template. Automatically handles Nginx Proxy Manager authentication when configured.

Parameters
Name Location Type Description
app_id path integer Database ID of the app
Responses
Status Description
200 Stats fetched successfully (ok may be false if upstream call failed)
404 App not found or no API configured
Example Response
{ "ok": true, "display": "42 active hosts" }
POST /api/apps/stats/batch

Fetch stats for multiple apps in parallel (up to 20 concurrent requests). Returns a map of app ID to result.

Request Body
{ "ids": [1, 2, 3] }
Response
{ "results": { "1": { "ok": true, "display": "online" }, "2": { "ok": false, "display": "error: connection refused" } } }

⚡ Custom Commands

GET /api/custom/commands

List all saved custom HTTP command shortcuts, sorted by name.

Response
[ { "id": 1, "name": "portainer-status", "method": "GET", "url": "http://portainer:9000/api/status", "headers": "{}", "payload": "", "jq_filter": ".Status" } ]
POST /api/custom/commands

Create a new custom command or update an existing one (matched by name). All fields except name and url are optional.

Request Body
{ "name": "portainer-status", "url": "http://portainer:9000/api/status", "method": "GET", "headers": "{}", "payload": "", "jq_filter": ".Status" }
Response
{ "status": "ok" }
DELETE /api/custom/commands/{cmd_id}

Delete a saved custom command by ID.

Parameters
Name Location Type Description
cmd_id path integer ID of the command to delete
POST /api/custom/run

Execute an arbitrary HTTP request from the server side. Response body is truncated at 20,000 characters.

Request Body
{ "url": "https://httpbin.org/get", "method": "GET", "headers": "{\"Accept\": \"application/json\"}", "payload": "" }
Response
{ "ok": true, "status": 200, "body": "{...}", "truncated": false }

🤖 AI / Ollama Integration

GET /api/ollama/models

Query the configured Ollama server and retrieve the list of available locally-cached models.

Response
{ "ok": true, "models": [ "llama3.2:latest", "mistral:latest" ] }
POST /api/ollama/ask

Send a single prompt to the configured Ollama model and receive the full response. Timeout: 120 seconds.

Request Body
{ "prompt": "What is the capital of France?" }
Response
{ "ok": true, "response": "The capital of France is Paris." }
POST /api/ollama/chat

Engage in multi-turn conversation with Ollama. Automatically prepends the system prompt configured in Settings. On context overflow (Ollama 500 error), history is trimmed and retried automatically.

Request Body
{ "messages": [ { "role": "user", "content": "Hello!" }, { "role": "assistant", "content": "Hi there!" }, { "role": "user", "content": "What can you do?" } ] }
Response
{ "ok": true, "response": "I can help with...", "trimmed": false }

🔧 Utility

POST /api/reorder

Persist a new sort order for apps or categories by accepting an ordered list of IDs.

Request Body
{ "items": [3, 1, 2], "type": "app" }
Parameters
Field Type Values Description
type string "app", "category" Whether to reorder apps or categories
items array integer IDs Ordered list of IDs representing the new sort order
Response
{ "status": "ok" }
